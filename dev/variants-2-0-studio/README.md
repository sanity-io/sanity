# Variants 2.0 design studio

A Studio that shows the Variants 2.0 designs working together, one surface per handoff
component (C1 to C8), each with any number of options (A, B, C, ...).

```
pnpm install                              # from the repo root
pnpm --filter sanity-variants-2-0-studio dev   # http://localhost:3350
```

Project `ppsg7ml5`, dataset `variants-2-0` (private): Nordic Books plus every state in `PERMUTATIONS.md`.
Seed or refresh it with `pnpm seed` (needs `sanity login`); inspect with `node seed/verify.mts`.
Override with `SANITY_STUDIO_PROJECT_ID` and `SANITY_STUDIO_DATASET` (`northfold` switches to the Northfold schema).

## How options work

- `options/registry.ts` lists each component and its options. Add an option by adding an entry.
- `OptionSlot` renders whichever option is in force; a missing renderer shows a placeholder.
- The floating control (bottom left) picks the Nth option for every component (A, B, C, ...) or `Final`.
- Per-component overrides are in the same panel. Choices persist in localStorage.

```tsx
<OptionSlot component="c3" options={{a: <PopoverV1 />, b: <FlyoutV2 />}} />
```

Pinned to the Studio revision Storybook uses (`21388ff`), so the real parts match.

## Stock Studio first

The `beta.variants` flag is off, so the Studio is stock (no Variant selector, no Variants tool,
no inventory). Variants 2.0 designs are additions on top of it, mounted through `OptionSlot`.

## Presentation and scheduled drafts

- Presentation previews `SANITY_STUDIO_PREVIEW_ORIGIN` (default `http://localhost:3456`, the Northfold storefront).
  The storefront has no visual-editing or draft mode yet, so this is a plain preview without overlays.
- Scheduled drafts is switched on explicitly in `sanity.config.ts`.

**Localization plugin** (switch `localization`, group "Localization plugin"; presets "Open beta (locked) + document-level localization", "+ field-level localization", "+ both localization plugins"). A scenario, not a design choice: how teams localize in open beta, before variants. A off (default); B the document-level plugin (`@sanity/document-internationalization` 6.2.43): each language is its own document, joined by a `translation.metadata` document, with a **Translations** menu in the document header (English, Danish, Swedish, Norwegian: open or create a version, Manage Translations) and a language badge; C the field-level plugin (`sanity-plugin-internationalized-array` 5.3.6 with `@sanity/language-filter` 5.0.23): ONE document per book with every language inside its fields (the "Book (field-level)" list), the plugin's "Showing all" filter in the document header, and a **locale pill** in the navbar (a third pill: "All (4)", "Show all locales", a flag and a check per language) that chooses which languages the form shows; D both, side by side. Neither plugin draws anything in the navbar: the locale pill is drawn here from the language filter's own state (`useLanguageFilterStudioContext`), the same state its header button uses. Data: `node seed/seed-translations.mts` (safe to run again; text in `seed/translations.json`): Danish, Swedish and Norwegian versions of the Nordic Books content (books, live books, series, publishers, places: 25 originals, 75 translations, 25 metadata documents) and the 12 books again as field-level documents (`fl-<book id>`); authors and the E9 fixtures are not translated. With the plugin off the Content list shows English documents only and hides the metadata and the field-level types (`localization/structure.ts`); the shipped Variants tool is core and lists every document. Checks: `node journeys/verify-localization.mts` (13 checks).

**Open beta (locked)** (preset `open-beta-locked`, `design=show.a,stage.open-beta,navLayout.b,c1.b,c2.c,c4.a`; the default preset). Direction from Faheem after the 21 Oct call with Andrej: no dedicated perspective bar or row; the global perspective is two chips in the navbar, and local versus global works per document. It reuses the existing switches and adds one option to three of them:

- Global (navbar, `c1` B, Figma C1 option B 192:3139): two controls, the stock state control (Drafts, Published or a release; its menu unchanged) and ONE added Variants control ("Default" at rest; one flat list for the one dimension with a Default row; applied it shows ONE value and a cross), the same 33 px rounded size. No row, no bar. The Variants control owns no state: the router's `variant` param is the only copy of the choice. The same controls are in every tool. Tools left, search and Create right (`navLayout` B).
- Local, following global (`c2` C, Figma C2 "Document header · selected for open beta" H1 to H4): the document header shows the state control collapsed to one rounded pill (the layer: Drafts, Published or a release) and a "N Versions" pill that opens the inventory side panel (`c4` A; the stock Versions button and the footer's "Manage versions" are hidden). No grouped pills, no variant chip, no toggle. A pane that follows global says nothing more.
- Local, diverging: clicking the state pill opens a row "Local perspective" under the header (the layer, the variant, "Follow global perspective") and the header pill steps aside (H2). When a change makes the pane differ from global, the row collapses and the header says "Local" before the pill (H3). "Follow global perspective" returns the pane to global. A reference pane opens following global and is unlocked the same way. The local address is the pane params `localPerspective` and `localVariant`.
- Compare and review are off (fast follow); their switches stay.
- A browser that already has a saved choice keeps it; pick "Open beta (locked)" in the preset bar to switch, or open a link with `preset=open-beta-locked`.

## Open beta header (Figma C2, phase 1: studio-only)

With `c2` = C (the Open beta (locked) default) the document header shows the perspective circle (`pane/LocalPerspective.tsx`: a muted outline cube while the pane follows the global perspective, a purple one when it holds its own; solid lines, no dashes) and the pill "<title> · N versions", which opens the inventory inspector. The footer's publish action names the shown variant (`pane/targetLabel.ts`). Per-spec-ID checks: `node journeys/verify-header.mts` (screenshots in `journeys-captures/e9-header/`). Phase 2 (one header across form and inspector, tab row, navbar section, "…" menu) needs core seams and is not in this commit.
